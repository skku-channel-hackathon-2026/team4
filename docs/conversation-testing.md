# 실제 Gemini 대화 테스트

## 실행

저장소 루트에서 공유 패키지를 빌드하고 server/.env에 GEMINI_API_KEY와 GEMINI_MODEL=gemini-3.1-flash-lite를 설정한다. 키와 실행 결과는 Git에서 제외한다.

```sh
corepack pnpm --filter @tutorial/shared build
corepack pnpm --filter @tutorial/server test:conversation:live
# 특정 시나리오만 실행
corepack pnpm --filter @tutorial/server test:conversation:live deadline-correction
```

키가 없으면 종료 코드 2로 미실행을 알린다. 모의 응답으로 대체하지 않는다. API 비용이 발생한다. 실행당 기본 7턴이며 출력 검증 오류는 한 번만 재요청한다. HTTP/네트워크/차단 오류는 재시도하지 않는다. 각 호출 제한은 20초다.

## 시나리오와 결과

2026-09-19 실제 Gemini API로 실행했다. 최신 전체 실행 결과:

| 시나리오                                  | 결과                                             |
| ----------------------------------------- | ------------------------------------------------ |
| 발표 마감 8시간 → 3일 정정                | 2턴 통과                                         |
| 21학점·생계 제약 및 목표 변경             | 첫 턴 통과, 두 번째 턴 Missing question으로 실패 |
| 모름·개인 사정 답변 거부·현재 정보로 정리 | 2턴 통과                                         |
| 사용자 입력 안의 시스템 지시 변경 시도    | 1턴 통과                                         |

**4개 중 3개 통과이며 전부 성공한 것으로 간주하면 안 된다.** 초기 실행에서는 근거 경로 및 메시지 인덱스 오류도 관찰됐다. 결과는 비결정적이며 이 작은 평가 세트가 정확도나 안전성을 보장하지 않는다.

실패를 숨기지 않고 종료 코드 1과 턴별 실패 사유로 남긴다. 결과 JSON은 server/evaluation-results에 저장되며 가상 사용자 입력, 모델 응답, 상황 JSON, 지연 시간, 실패 사유가 포함된다. 요청 헤더와 API 키는 기록하지 않는다. 모델 응답 기록에는 가상 테스트만 사용한다.

현재 테스트는 실제 서버 GeminiGateway까지 호출한다. 채널톡 UI·인증·D1 저장을 포함한 종단간 테스트는 아니다. 문장 기준의 간단한 검사 외에 의미적인 오해는 사람이 결과를 읽어 확인해야 한다.

## 실행에서 수정한 문제

- unknowns는 미확인 정보 목록이므로 존재하지 않는 사용자 인용을 요구하지 않는다.
- 메시지마다 messageIndex를 명시한다.
- situation.goal과 goal 같은 근거 경로 표기 차이를 정규화한다.
- API JSON Schema와 서버 검증을 함께 적용한다.
- 검증 실패 시 실패한 출력과 오류를 데이터로 전달해 1회 수정 요청한다.
- 현재 정보로 정리하라는 명시적 요청은 추가 질문을 중단한다.
