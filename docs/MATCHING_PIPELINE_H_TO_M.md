## 입력과 범위

검색 키는 학생이 확인한 `Situation` 스냅샷과 확인한 `ActionCandidate`다. `attemptedActions`와 `consideredActions`는 분리되어 있으며, 이미 시도했다는 이유로 검색할 행동으로 자동 승격하지 않는다. 함수는 본인 세션·확인 revision·현재 요청 revision을 검증한다.

A→H의 모델 추출은 main 구현을 사용한다. 이번 로컬 벤치마크는 H 이후 사례 매칭만 검증한다. Gemini 추출의 정확도를 측정한 결과가 아니다. PR #18의 별도 구조를 가져오지 않았다.

## 점수와 필터

| 항목      | 최대 가중치 | 근거                               |
| --------- | ----------: | ---------------------------------- |
| 문제 유형 |          20 | 확인된 problemType 일치            |
| 상황 맥락 |          20 | 실제 상황·진행 설명의 유사성       |
| 주요 제약 |          20 | 명시 조건 비교 및 제약 문장 유사성 |
| 목표      |          20 | 목표 설명 유사성                   |
| 긴급도    |          20 | 양쪽에 확인된 시간 범주 일치       |

실제 행동은 점수 보너스가 아니라 필수 필터다. 같은 행동을 실제 수행한 후보 안에서 항목별 순위를 합산한다. 약한 문자열 겹침은 감점하고, 미확인의 배점을 다른 항목으로 옮기지 않는다. 여러 필드에 동일하게 반복된 사실은 배점을 나눠 중복 기여를 제한한다. 자세한 수식·실험은 [분산 가중치 보고서](MATCHING_DISTRIBUTED_WEIGHTS.md)를 참조한다.

텍스트는 이진 TF-IDF 단어/2·3글자 문자 조각 코사인으로 비교한다. 제목·편집 태그·성공/실패 결과는 대표 순위에 사용하지 않는다. 확인된 반대 서술은 해당 항목에 음수로 기여하며, 점수는 내부 정렬용으로만 사용한다. 확률·정확도가 아니며 화면에 표시하지 않는다.

시간이 다르다는 이유 하나로 모든 후보 뒤로 보내지 않고 합산 점수로 정렬한다. 명시적 차이가 있는 사례는 여전히 reference이며 차이를 표시한다. 한 항목 이하의 긍정 근거만 있으면 강한 상황 문장 일치(context≥0.5)를 제외하고 reference로 제한한다. 문턱과 배점은 검증된 통계가 아닌 휴리스틱이다. 동점은 ID순이다.

## 참고·없음·미지원

- `matched`: 실제 같은 행동을 했고 최소 상황 관련성이 있으며 자동 검사에서 명시적 조건 차이가 발견되지 않음. 적용 조건 충족이나 성공을 보증하지 않음.
- `reference`: 같은 행동의 사례이나 상황 근거가 부족하거나 알려진 긴급도/제약이 다름. 차이를 표시하고 충분히 비슷하다고 주장하지 않음.
- `no_case`: 같은 행동을 실제로 한 승인 사례가 없음. 다른 행동의 사례로 채우지 않음.
- `no_case` + `unsupported: true`: 학생 행동을 지원 태그로 연결하지 못함. 기존 행동 확인 화면에서 의미를 한 번 선택하거나 미지원으로 진행하도록 확인한다. 직접 쓴 문장은 키워드 하나로 자동 분류하지 않는다.

명시적 조건 검사는 같은 이름의 수치(소수 평점 포함), 같은 주제의 시간 단위 변환(시간/분), 정확히 같은 주제의 있음/없음·가능/불가에 한정한다. 알려진 urgency 값이 다르면 시간 차이로 처리한다. 상황·목표의 거의 동일한 주제에 붙은 단순 부정 표현도 검사한다. 자유문장 전체의 의미·범위·복잡한 부정·인과는 판단하지 않는다. 원문 적용 조건은 확인 필요로 남긴다.

## 추가 사례와 결과 해석

대표 사례를 먼저 정한 뒤 나머지 관련 후보 중 `receipt.status`가 다른 경과를 우선 보존하고 최대 두 개를 추가한다. 해결/일부 해결/진행 중은 선배가 기록한 경과 분류이지 자동 인과 판정이 아니다. 같은 경과 안에도 서로 다른 결과가 있으므로 남는 자리는 기존 순위순으로 채운다.

추가 사례는 기존 카드 안의 “같은 행동의 다른 경과 보기”를 펼쳐 읽는다. 결과 원문·후속 결과·미해결·비용을 그대로 보여 준다. 여러 행동이 있으면 순번을 표시하고 “사례 전체의 결과이며 특정 행동 하나의 효과로 단정할 수 없음”을 안내한다. 별도 행동별 관찰 시점이 없으면 없다고 명시한다. 시점을 만들어내지 않는다.

대표·추가 카드를 합쳐 같은 사례가 여러 행동에 나오면 중복 근거임을 표시한다. 상세/도구/피드백은 추가 사례도 처리하며, 비교 revision이 달라진 예전 카드의 피드백은 거부한다.

## main UI 사용

main의 `Compare`, `ActionCard`, `ActionsReview`, `CaseDetail`, `CopyButton`을 재사용한다. 새 디자인이나 CSS 파일은 만들지 않는다. 필요한 변경만 기존 화면에 추가했다.

- 사례 ID, 실제/가상 배지, 비교 정보가 있는 항목.
- 같은 행동의 다른 경과를 펼치는 영역.
- 미지원 행동의 의미 확인.
- 학생이 상황 확인에서 채운 항목은 결과의 오래된 미확인 목록에서 제거.

`ActionResult`에 선택 필드 `comparedFields`, `alternatives`, `unsupported`가 추가됐다. 기존 결과 키는 유지된다. 새 함수 이름·DB 마이그레이션은 없다. 추후 운영에 반영할 때에는 출력 스키마 변경에 따른 앱 등록 갱신 필요 여부를 운영자와 확인한다.

## 실제/가상 모드

서버 `FAILFAIR_CASE_SOURCE`는 기본 `real`이다. `demo`를 명시해야 가상 시연 사례만 검색한다. 두 종류가 한 비교에 함께 나오지 않는다. 모드는 비교 시 세션에 저장하고 상세·도구 조회에서도 source가 달라진 사례를 거부한다. real 모드에서 실제 승인 사례가 없으면 빈 결과가 정상이다.

Wrangler는 `.dev.vars`, Node 실행은 `server/.env`를 사용한다. 테스트용 환경에서만 `FAILFAIR_CASE_SOURCE=demo`로 설정한다. 이 값은 API 키가 아니며, 매칭 자체는 외부 API 호출이 없다.
