클라이언트가 보낸 contextMeta를 저장 근거로 신뢰하지 않는다. 서버가 기존 근거와 최종 값을 비교한다. studentContext가 있는 새 경로에서는 그 구조를 원본으로 사용하며 v0.3 메타데이터를 중복 저장하지 않는다.

## 함께 포함한 현재 작업

`studentContext`의 항목에 사실·목표·선호·제약·추정·미확인을 구분하고 변경분을 병합한다. 기존 Situation과 검색 인터페이스는 유지한다. 자세한 계약과 검증 한계는 [STUDENT_CONTEXT_V1.md](STUDENT_CONTEXT_V1.md)에 있다.

새 구조에서 Gemini가 실패하면 기존 상태를 규칙 기반 추측으로 바꾸지 않고 재시도 오류를 반환한다. 기존 세션과 초기 설정의 fallback 정책은 유지한다.

## 검증

- 최신 main `0af2929` 통합 후 서버 테스트 131개·UI 테스트 13개 통과.
- 독립 context-contract 테스트 22개 통과.
- 타입 검사, 프런트엔드 lint, 전체 포맷 검사 통과.
- Vercel·Cloudflare 배포용 빌드와 Vercel 로컬 스모크 테스트 통과. 실제 배포는 실행하지 않았다.
- 통합 테스트는 실제 함수·게이트웨이 검증·세션 저장 흐름을 사용하며 Gemini 응답만 대체하고 저장소는 실제 SQL을 실행하는 로컬 SQLite D1 대역을 사용한다. 실제 Channel Talk 배포 실행은 아니다.

## 알려진 한계

PR #14의 다섯 지적과 별개로, 실제 Gemini가 정정을 다른 id의 새 사실로 추가해 옛 사실을 남기는 의미 해석 오류는 아직 남아 있다. 이전 실제 평가 기록을 강화된 기준으로 재검토하면 3개 중 2개를 만족했다. 이를 숨기거나 특정 시연 대본의 답을 외우게 하는 예외 규칙을 추가하지 않았다. 이번 PR은 범용 분류 정확도 100%나 시연 대본의 자동 재현을 주장하지 않는다.

## PR #18 충돌 해결 (2026-09-19)

최신 main의 D1 세션·응답 원자 저장과 PR #18의 저장 전 인용 검증이 같은 위치에서 충돌했다. 인용 검증이 성공한 뒤 기존 revision을 기준으로 세션과 응답을 함께 저장하도록 두 동작을 유지했다. main의 UI 재시도·미전송 메시지 보존 변경도 유지했다.

이전 Map 저장소 형식을 사용하던 context-lifecycle 통합 테스트를 새 D1 저장 인터페이스로 전환했다. 잘못된 인용일 때 세션과 요청 응답이 모두 저장되지 않고, 같은 요청 ID로 정상 데이터를 다시 제출하면 한 번만 저장되는 회귀 검사를 추가했다. 별도 로컬 매칭/벤치마크 작업은 이번 PR에 포함하지 않는다.
