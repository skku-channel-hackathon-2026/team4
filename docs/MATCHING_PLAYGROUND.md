# 직접 매칭 검사하기

주소: http://127.0.0.1:8798 (로컬 서버가 실행 중일 때만 접속 가능)

1. 기본 예시를 그대로 검사해 결과를 확인한다.
2. 고민·목표·제약을 본인의 표현으로 바꾸고 **검사하기**를 누른다. 문제 유형은 모르면 비워도 된다. 자동 추출하지 않으므로 기존 예시의 유형이 내 고민과 다르면 반드시 지운다.
3. 오른쪽에서 대표 사례와 전체 후보 순위, 5개 항목의 기여, 선배 원문, 차이/미확인을 확인한다.
4. **항목 제외 실험**에서 한 항목을 선택하고 재검사해 이전 선택과 비교한다. 선택한 항목은 0점이 되고 나머지 배점은 유지된다.
5. 이상한 결과는 **결과 JSON 저장**으로 내려받는다. 입력·후보 원문·점수·출력이 함께 들어 있어 재현할 수 있다. 내려받은 파일에는 작성한 고민이 포함된다.

일반 예시는 bundled 가상 사례 20개를 사용한다. ‘한계 검사’ 예시는 합성 대조 사례 2개만 검색한다. 예시 선택 후 **예시 불러오기**를 눌러 적용한다. 같은 카테고리·승인 상태·같은 실제 행동으로 걸러 검색하며 없는 행동의 사례를 만들어내지 않는다. JSON 안의 결과 카드에는 추가 사례도 포함된다.

이 화면은 상황 추출 이후 H→매칭 결과를 직접 검사하는 개발 도구다. Gemini 대화 추출, 실제 DB, 채널 인증·배포를 시험하는 화면은 아니다. 서비스 UI와 알고리즘 자체는 이번 도구 추가로 바꾸지 않았다. 기본 출력 점수가 100이어도 성공 확률 100%를 뜻하지 않는다.

## 다시 실행

저장소 루트에서:

```sh
corepack pnpm --filter @tutorial/shared build
corepack pnpm --filter @tutorial/server inspect:matching
```

기본 포트는 8798이며 `MATCHING_PLAYGROUND_PORT`로 변경할 수 있다. 주소는 `localhost` 대신 출력된 `127.0.0.1` 주소를 사용한다. 서버는 루프백에만 열리며 입력을 파일이나 DB에 저장하지 않는다. API 키가 필요 없다.

검증: 서버 타입 검사 통과. 브라우저에서 기본 사례 선택과 문제 유형 제외 후 해당 항목의 기여가 20→0으로 변하고 총점이 100→80으로 변하는 것을 확인했다.
